# ADR-039 — Audio hooks: sound, music and ambience through the frame buffer

**Status:** Accepted (coordinator, 2026-10-25, owner delegation). Roadmap M3. Builds on ADR-002 (one render crossing per
frame), ADR-007 (placeholder content), ADR-027 (weather and day/night), ADR-033 (settings: the volumes were stored and unused).

## Context

The game is silent. The roadmap asks for ambient sound and music hooks within the interop budget of ADR-002, and ADR-033 stored
a music volume, a sound volume and a mute switch that nothing reads. Real audio is M6 (own music and sound effects); this
ADR builds the *hooks* and ships tiny placeholder sounds that are Nosum's own.

## Decision

- **D1 — Sound rides in the frame's command buffer.** `RenderCommandBuffer` gains three commands, appended to the existing set (older
  ids keep their meaning): texture `-7` plays a sound once (`PlaySound`: sound id, volume 0–100, pan −100–100), `-8` sets the music
  track (`SetMusic`, 0 is silence), `-9` sets the ambient loop (`SetAmbientLoop`: loop id, volume). They draw nothing. So audio
  adds **no interop crossing**: the one `submitFrame` call per frame carries it.
- **D2 — `SoundCues` (engine, platform-free).** Hooks ask for sounds between frames; the scene writes the cues into the buffer
  right after `Begin` (before the draws, so a full buffer never drops sound). Preallocated arrays, nothing allocated per frame. Per
  sound minimum interval (a sound asked for again sooner is dropped: footsteps, coin streaks), at most 16 sounds wait for a frame,
  and music / ambient loop commands are sent **only when they change**. It knows ids, not meanings.
- **D3 — Web Audio in `audio.js`, a sibling of `renderer.js`** (no package). `renderer.js` only forwards commands `-7..-9` and
  re-exports the load/volume functions; the rest of the audio code is in its own module so `renderer.js` stays free of it.
  - Files are fetched and decoded **once at load** (`OfflineAudioContext.decodeAudioData`, which needs no gesture); a file that
    fails to load, or an id with no file, is silence and never an error.
  - The real `AudioContext` is created on **the first user gesture** (pointer, mouse, key or touch) and resumed there; until then
    one-shot sounds are dropped and music / ambient requests are remembered and start when audio unlocks (browser autoplay rule).
  - Two buses (music, sound effects) carry the settings gains; sounds use at most 16 voices; the music and the ambient loop
    cross-fade when their id changes.
- **D4 — Hooks (what plays when).** Sound ids and rules are `Nosum.Wasm.ViewModels.Audio.AudioCatalog`.
  | Hook | Sound | Source |
  |:--|:--|:--|
  | Tool swing | one per tool: hoe, watering can, axe, pickaxe, scythe (and the milk pail) | the action key in `PlayerActions`, when pressed (the server still decides the outcome) |
  | Harvest, planting, can refill | harvest chime, seed pat, splash | `FarmChannel.UseCompleted` (the server's answer) |
  | Pick-up | pickup blip; a neighbour's pickup is quieter and panned | `GroundItemChannel.PickedUp` |
  | Coins | coin | `WalletChannel.Changed`, the balance moved |
  | Door / warp | door swoosh | the scene swapping the map, and the ladder answer |
  | UI | open, close; a click on any button | panel changes in `ToolbarViewModel`; the click is a DOM listener in `audio.js` (plays in the browser, never enters .NET) |
  | Footsteps | footstep, every 0.34 s while walking, minimum 0.2 s apart | the scene's `FootstepTimer` |
  | Rain ambience | rain loop, volume 55 (rain) or 85 (storm); **outdoors only**, snow and fair weather are silent | `WeatherRules` of the server calendar, as the sky uses it |
  | Music | track id per season and day/night (`MusicTrackIds.For`: 1 spring day … 8 winter night; night is 20:00–06:00) | the server calendar |
- **D5 — Settings.** `SettingsApplier` sends the two gains (`VolumeCurve.Gain`: the slider squared, 0 when muted) through one
  `setAudioLevels` call **when the settings change** (never from the frame). Changing a volume or the mute switch takes effect on the
  next frame's sounds and ramps the music.
- **D6 — Placeholder audio (ADR-007).** **No Stardew audio and no downloaded audio.** The sounds are generated by
  `tools/synth_sounds.py` (Python standard library only, deterministic): sine waves with pitch glides, white noise through one-pole
  low/high-pass filters, linear-attack / decaying envelopes, a cross-faded 3 s noise bed for the rain loop; 22.05 kHz, 16-bit mono
  WAV, 264 KB for all fifteen files, committed in `wasm/Nosum.Wasm/wwwroot/audio/`. They are Nosum's own, so unlike `assets/` they
  are not third-party placeholder content, but they are placeholders in quality. `--check` verifies the committed files match the
  script. Music tracks had ids and no files until M6; their own loops are in the implementation notes below.

## Alternatives considered

- **A JS call per sound (`IJSRuntime` or a `[JSImport]` per cue).** Simplest, but breaks ADR-002 D1/D4 and costs a crossing per
  footstep; rejected.
- **Decoding in the real `AudioContext`.** Needs the gesture first, so the first sounds would arrive late; the offline context
  decodes at load and its buffers play in any context.
- **Putting audio in `renderer.js`.** It already holds input, touch and drawing, and other branches edit it; a sibling module avoids
  the conflicts and keeps the audio testable on its own.
- **Click sound routed through .NET.** Every button would need wiring; a delegated DOM listener is one listener and costs no crossing.

## Consequences

- The command-buffer encoding grows by three ids; `renderer.js` and `RenderCommandBuffer` change in the same commit.
- Sounds are feedback for the key press, not for the server's outcome: a swing that the server refuses still sounds.
- A browser that blocks audio entirely (or has no Web Audio) plays nothing and the game is unaffected.
- Replacing the synthesised sounds with better own sound effects is still open: same file names, or edit `AudioCatalog`.

## Revisit when

Better own sound effects are wanted (the synthesised ones are placeholders in quality); or positional sound for other players' tools
and footsteps is wanted (the pan field is already in the command).

## Implementation notes (M6: own music)

- **Made by `tools/synth_music.py`**: Python standard library only and deterministic (a fixed seed per track); `--check` fails when the
  committed files differ from the script. Like the sounds, every sample is computed from square, triangle and sine voices with simple
  envelopes; nothing is recorded, downloaded or taken from any game.
- **Eight tracks, one per `MusicTrackIds.For` id** (1 spring day, 2 spring night … 8 winter night; night is the same dusk-to-dawn rule as
  the sky). Each is a whole number of bars, so it loops seamlessly: a note that runs past the end wraps to the start, and the one-pole
  low-pass that softens the square voice is run twice so its state at the loop point matches the start.
- **Style.** Day tracks are brighter and busier: major keys, triangle arpeggios and bass, a square melody in spring and summer, a sine pad
  with seventh chords in fall. Night tracks are slower with fewer voices (sine only). Winter is sparse: a sine pad and one melody note per
  chord. Progressions: spring C G Am F, summer G D Em C, fall F Dm7 B♭maj7 C7, winter Am F C G; the night tracks use minor keys.
- **Format.** 8-bit mono PCM WAV at 22.05 kHz, the eight files about 5.7 MB in total, each 30 to 38 s. 16-bit would be about 10.6 MB for
  the eight tracks alone, over the budget; OGG needs an encoder, which is not in the standard library. `audio.js` decodes each file once at
  load, as it does the sounds.
- **Catalogue.** `AudioCatalog.Files` lists the eight `AudioKind.Track` entries by file name (`music_<season>_<day|night>.wav`);
  `AudioCatalogTests` checks that every music id has a file and that each file is a mono 22.05 kHz 8-bit loop of 30 to 60 s.
- **Unchanged.** The frame command buffer, the interop budget and `audio.js`'s design. The music bus takes the music gain from the settings
  (mute included), and playback starts after the first user gesture.
