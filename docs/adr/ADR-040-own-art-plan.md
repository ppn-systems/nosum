# ADR-040 — Own art plan: what to replace, in what order, and how to prove it

**Status:** Accepted (coordinator, 2026-10-25, under the authority the owner delegated; see "Coordinator review" below). Roadmap M6, phase 0. Builds on ADR-007 (placeholder content, D5), ADR-004 (own-art provenance), ADR-005 (3/4 view),
ADR-006 (layered characters), ADR-031 D9 (placeholder content gate) and ADR-039 (audio).

## Context

The game runs on unpacked Stardew Valley files (ADR-007). Before any public release every one of them must be replaced by Nosum's own
art in the same layouts (`docs/design/roadmap.md`, M6). `assets/` holds 1,994 files; the game loads far fewer.
[`docs/art/inventory.md`](../art/inventory.md), generated by `tools/Nosum.AssetInventory` from the maps and the code, is the measured scope:

41 images and 50 maps of 1,994 files; 4,922 of the 33,749 cells in those images are drawn (14.6%). A cell is one square of the file's grid; a
frame is a used cell of a walk, direction, growth or animation sequence (counted inside the cell total); a cell several packages draw belongs to
the first of them. Fonts: the only font loaded, VT323, is SIL OFL and stays. Audio: no audio file is loaded yet; ADR-039 adds the hooks and
Nosum's own placeholder sounds, so the package is sized when the sound list exists. The report also lists every tile index each map places, per
layer and sheet, and the animated tiles.

## Decision

- **D1 — Art direction.** 16 × 16 px tiles on a 16 px grid, 3/4 top-down (ADR-005; PixelLab "low top-down"), characters and tall objects on 16 × 32
  frames, drawn at a whole-number scale with smoothing off (ADR-007 D1). One shared palette of at most 48 colours [Assumption: chosen for the
  warm farm look; the owner may change the number, the rule is "one palette for every file"], supplied to every generator that accepts one
  (PixelLab `palette` / `max_colors`). Outline rule: objects, characters and animals get a 1 px outline in a darker tone of their own fill (never
  pure black); ground and terrain tiles have no outline, so they tile seamlessly. Light comes from the top left; shadows are drawn as part of
  the sprite, not blended in code.
- **D2 — Replacement keeps every layout.** Each listed file is replaced by a file of the same path, the same pixel size and the same grid, with the
  same content in each cell the inventory lists as used (a grass tile stays grass at its index; a walk frame stays at its frame position). No code
  changes: the code addresses cells by sheet and index (ADR-007 D2). Sheets the maps load but draw nothing from (0 used cells, for example
  `Maps/paths.png`) still need a file of that size; a transparent image is enough.
- **D3 — Work packages in the priority order of the table above**, because the first hour of play (the farmer, the Farm, the Town, the
  FarmHouse) is what a reviewer sees first, and the farmer layers are the smallest and the hardest. The "remaining maps" package is last
  because it is the mine (40 floor plans on 3 sheets) plus the coop and barn interiors and the outdoor maps that reuse the core sheets.
- **D4 — Production options per package.** Every package picks one or more:
  - **PixelLab** (the MCP tools in the session): `create_character` + `animate_character` (humanoid and animal direction sets, template walks),
    `create_topdown_tileset` (a Wang set of two terrains, 16 or 25 tiles) and `create_tiles_pro` (batches of independent tiles), `create_map_object`
    (buildings, trees, props up to 400 px), `create_ui_asset` (panels and buttons), `create_font`, plus `pixelart_workbench` for exact edits.
    Output is AI-generated: check PixelLab's terms and the ownership of generated art before release (ADR-004 provenance rules), and
    record the prompt, seed and date of each generation next to the file in a provenance note.
  - **Hand pixel work** (owner or artist) for what generators draw badly: the layered farmer parts that must line up pixel for pixel
    (body, arms, pants, hair, hats, shirt pieces), and animation frames that must keep an exact silhouette.
  - **Commissioned art** with a work-for-hire or full-assignment contract; the right route for the farmer and the title picture.
  - **Open-licensed packs, CC0 only** (no attribution duty, commercial use allowed). Candidates, **all unverified: nothing here was opened or
    license-checked in this phase**; confirm the license on the pack's own page and keep a copy of it before using anything:
    Kenney Tiny Town and Roguelike/RPG Pack, 16 px (https://kenney.nl/assets/tiny-town, https://kenney.nl/assets/roguelike-rpg-pack; Kenney states CC0);
    Ninja Adventure Asset Pack, 16 px with characters, tiles and sounds (https://pixel-boy.itch.io/ninja-adventure-asset-pack; stated CC0);
    Kenney audio packs (https://kenney.nl/assets/category:Audio; stated CC0). Packs under CC-BY, CC-BY-SA, GPL or a custom "free for
    games" license (for example the Liberated Pixel Cup sheets) are excluded. A pack rarely matches the cell layouts of D2, so it is used to
    seed redrawing, not to drop in.

  Suggested route per package: farmer — hand or commission, PixelLab for concepts; terrain — PixelLab tilesets, then hand fixes; items,
  tools, nodes, buildings, UI — PixelLab objects and panels, packs for gaps; animals — PixelLab quadruped character plus template walk;
  fonts — keep VT323; remaining maps — PixelLab tilesets and pack tiles; audio — ADR-039, packs and own recordings.
- **D5 — Cost estimate in PixelLab generations.** Assumption (from the brief): one generation per tile set, per character direction set, per
  animation of a set, or per object. Tile sets and tile batches are counted at 16 cells each. The units are jobs; PixelLab bills its own
  "generations" per tool (a standard top-down tileset 1, a pro tileset 15, a v3 character 2–9, a UI panel 10–25, a font 15; checked against
  the tool descriptions, nothing was generated), so the money figure comes from `get_balance` and the price list when the budget is set.

  Plan for twice that (about 1,000 jobs) to cover rejected results and re-rolls.
- **D6 — Verifying a replaced sheet.** `dotnet run --project tools/Nosum.AssetInventory -- --release` checks every listed file against
  `docs/art/placeholders.sha256`, which records the SHA-256 and pixel size of each placeholder as unpacked (maps: tiles × tile size). A file whose
  hash still matches is a placeholder (exit 1); a file that is missing or no longer has the recorded pixel size breaks its layout (exit 2); all
  others are replacements. The same-size check is the grid check, because the grids are fixed per file (the report's *Grid* column). Two checks
  come with the first replaced file, not now [Assumption: needs an image decoder, which only `tools/Nosum.AtlasPacker` references]: that every used
  cell of the replacement is not empty, and that no pixel of a replacement uses a colour outside the D1 palette. The existing tests keep covering the
  code side: `ThemeSpritesTests` (UI rectangles inside their sheets), `GameMapsTests` (every map and sheet is linked), `NodeSitesTests`.
- **D7 — Keeping the inventory true.** `tests/Nosum.UnitTests/Tools/AssetInventoryTests.cs` fails when: code names a file of `assets/` that the report
  does not list; a project links a file of `assets/` that the report does not list; the report's files or sizes differ from what the code loads (a new
  animal sheet, map or prop); a new file is not in `placeholders.sha256`; or `NodeSprites` draws an objects-sheet cell the tool does not know.
  Cell counts may drift between regenerations (adding an item does not fail the build); `--check` is the strict mode for the release gate and
  fails on any difference.
- **D8 — Release gate.** ADR-031 D9 already gates public builds: `assets/PLACEHOLDER_CONTENT` is a marker that `deploy/check-placeholder-art.sh` and the
  MSBuild target `deploy/PlaceholderGate.targets` check (on `origin/feat/ops` when this ADR was written, not yet on `master`). This ADR adds no second
  gate. It adds the rule for removing the marker: the marker is deleted only in the commit after which `Nosum.AssetInventory --release` exits 0,
  so "no listed placeholder file present" is what the existing gate stands for. Until then the gate refuses public packaging.
- **D9 — Map layouts.** The `.tmx` files are replaced like the sheets (D2), so the level layouts stay. Stardew's map designs are creative work too.
  Whether to redraw the layouts before release (warps, shop counters, node sites and tile coordinates in `Nosum.Gameplay` would change with them) is
  an owner decision; it is not in these estimates. See Consequences.

### Coordinator review (acceptance notes)

- **Core terrain and remaining maps (packages 2 and 11) are re-authored, not redrawn one for one.** Redrawing 4,086 Stardew cells to match their
  indices costs most of the budget and copies their layout too closely. Instead, a script fills the drawn tile layers of each hosted map with tiles
  from a small set of own terrain sets (PixelLab top-down Wang tilesets: grass, dirt, sand, water, path, cliff), choosing the set by classifying
  each placeholder tile into a terrain kind. Collision, warps, spawn tiles, counters, doors and every gameplay layer stay unchanged, so no code
  changes (the D1 rule still holds: gameplay coordinates are the contract, not tile indices). Buildings and props stay map objects drawn from
  package 7.
- This cuts packages 2 and 11 from about 257 generations to about 20–40 (one Wang set per terrain pair plus hand fixes). The estimate in D5 is
  kept as the upper bound until the first map is converted.
- The owner decides the budget: the PixelLab account is on a trial with 10 generations left, which is enough only for a farmer concept.

## Alternatives considered

- **Replace everything in `assets/`** — 1,953 files are never loaded; replacing them is wasted work. The inventory lists only what is loaded; the
  unlisted files are deleted from the release branch (roadmap M6).
- **Repack into atlases** (ADR-004) — the code addresses sheets by index (ADR-007 D2); repacking is a code change for no gain.
- **Re-grid to 32 px** — doubles the cell count and changes every table in the code.
- **Only open-licensed packs** — no pack matches the layouts of D2 and the farmer's layers; kept as an input to D4, not the plan.

## Consequences

- The scope is fixed and measurable: 41 images, 50 maps, 4,922 cells. The largest package, core terrain, is more than half of all cells.
- Replacing sheets keeps Stardew's map layouts; if the owner judges them derivative, D9 becomes a separate, larger piece of work with code changes.
- AI-generated art needs a provenance record per file and a check of PixelLab's terms before a commercial release; this is unresolved.
- The inventory tool references `Nosum.Gameplay`, `Nosum.Core` and `Nosum.Rendering`; a catalogue change that adds a sheet fails the unit test until the
  report is regenerated.

## Revisit when

The owner picks the production route per package, the sound list of ADR-039 exists (size the audio package), a first replaced sheet shows the D6 checks
are enough, or the owner decides on D9.
